# 自动化入门

自动化模块用于把脚本工具、执行目标、执行账号、作业参数和执行记录组织成可复用、可追踪的自动化作业。它解决的是“脚本分散、执行目标难统一、执行过程难追踪”的问题：通过工具库沉淀能力，通过组合工具编排流程，通过作业管理跟踪执行过程，通过定时作业和快捷服务把常用操作变成可管理的运维入口。

## 模块定位

自动化主要围绕“工具沉淀、目标管理、作业执行、服务化使用和基础配置”展开：

1. **作业管理**：集中发起、查看、接管、暂停、中止、重新执行和验证自动化作业。
2. **组合工具**：把工具、阶段、参数、执行方式、执行目标和并发策略编排成可复用作业模板。
3. **工具库**：管理内置工具、自定义脚本、工具版本、测试、审批和导入导出。
4. **资源中心**：通过资产、账号、标签和视图准备可连接、可筛选、可执行的目标。
5. **定时作业和快捷服务**：把固定任务变成定期自动执行或一键发起的服务入口。
6. **自动化配置**：维护工具分类、工具目录、操作级别、参数集、全局参数、场景和模板。

## 核心流程

一个自动化作业通常围绕“能力沉淀、模板编排、发起执行和结果追踪”形成闭环：

1. 管理员准备资产、账号、执行器组、工具分类、工具目录和参数集。
2. 管理员把脚本、命令或标准操作封装成工具，并通过测试和审批形成可使用版本。
3. 管理员创建组合工具，配置阶段、工具、参数、执行目标、并发策略和通知规则。
4. 执行人通过组合工具、快捷服务、定时作业或流程节点发起作业。
5. 系统根据执行方式、执行器组、账号协议和目标节点分发任务，并按阶段记录执行过程。
6. 执行人在作业管理中查看状态、日志、控制台、输入输出参数和节点结果，必要时接管、暂停、中止、重跑或验证。

> 注意：组合工具、工具版本、执行目标、账号、权限等配置会影响后续新发起的作业；已生成的历史作业通常以当时的配置和执行记录为准。

## 入门配置顺序

首次使用自动化模块时，建议先完成一条可跑通的最小链路：

1. 配置**执行环境**，确认 runner、执行器组、网络策略、资产和账号可用。
2. 配置**自动化基础数据**，准备工具分类、工具目录、操作级别和必要的参数集。
3. 选择**内置工具或简单自定义工具**完成测试，确认参数和执行方式没有问题。
4. 创建**最小组合工具**，只保留必要阶段、参数映射、执行目标和执行用户。
5. 使用普通用户账号发起一条测试作业，验证作业状态、日志、输入输出参数和节点结果。
6. 根据现场需要补充**定时作业**、**快捷服务**、通知策略、Tagent 服务和常见问题处理配置。

## 常见使用场景

### 手动发起自动化作业

执行人通过快速入口或组合工具详情发起作业，填写作业参数、选择执行目标和执行账号后保存或执行。作业运行后，可在作业管理中查看状态、控制台、节点日志、输入输出参数和执行记录。

### 编排标准运维流程

管理员先整理执行目标、账号和基础参数，再把内置工具或自定义工具放入组合工具中，按阶段配置执行方式、参数映射、目标筛选和并发策略。审批通过后，用户即可按权限发起作业。

### 定期执行固定任务

对于定时巡检、定时清理、定时同步等重复任务，可以创建定时作业，关联组合工具和定时器，并预设参数、执行目标和账号。保存后可先测试，再按计划自动运行。

### 封装常用快捷入口

如果某类作业经常由不同用户发起，且参数或执行目标比较固定，可以通过快捷服务配置目录和服务，让用户从服务目录直接发起作业，减少重复选择和填写。

### 处理远程连接和执行失败

作业失败时，通常先确认是否分配到执行器，再检查执行目标连接、账号协议、资产标签、参数映射和组合工具阶段配置。常见问题可优先参考自动化 FAQ。
