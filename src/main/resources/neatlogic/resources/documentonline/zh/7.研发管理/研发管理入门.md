# 研发管理入门

研发管理模块用于围绕项目、迭代、需求、缺陷和任务进行过程管理，帮助团队把研发计划、执行过程、状态流转和工作记录沉淀到统一平台中。

它的核心价值是：通过模板统一项目应用和字段规则，通过项目承载实际研发数据，通过工作台汇总个人待处理事项，让团队可以按统一流程跟踪需求、缺陷、任务和迭代进展。

## 阅读路径

可根据当前要解决的问题选择阅读入口。

- 如果需要了解研发管理模块的整体使用方式，阅读本文。
- 如果需要查看自己相关的待办、已办、上报和关注事务，阅读“工作台”。
- 如果需要创建或维护项目，阅读“项目管理”。
- 如果需要配置项目使用的应用、字段和状态流转规则，阅读“模板管理”。
- 如果需要了解迭代、需求、缺陷、任务等项目内功能，阅读“项目应用功能”。
- 如果需要维护需求或缺陷的紧急程度，阅读“优先级管理”。

## 模块定位

研发管理主要围绕“模板、项目、项目应用、工作台和基础配置”展开：

1. **模板管理**：定义项目创建时使用的基础配置，包括应用设置、属性设置、状态设置和 GitLab 配置。
2. **项目管理**：基于模板创建项目，并维护项目基本信息、人员组成、应用配置和项目状态。
3. **项目应用功能**：在项目中管理迭代、需求、缺陷、任务等数据，并支持状态流转、关联关系、工时花费和仪表板展示。
4. **工作台**：集中查看当前用户相关的待办、已办、上报和关注事务。
5. **优先级管理**：维护需求、缺陷等事务可使用的优先级数据。

## 入门配置顺序

首次使用研发管理模块时，建议先完成最小可用配置：

1. 在优先级管理中维护优先级名称、颜色和排序，用于区分需求、缺陷等事务的紧急程度。
2. 在模板管理中创建项目模板，并启用项目需要使用的应用，例如迭代、需求、任务、缺陷、测试计划、测试用例、GitLab、甘特图和仪表板。
3. 为需求、任务、缺陷、测试计划或测试用例配置属性和状态，明确字段展示、必填规则、状态流转关系和结束状态。
4. 如需在流转时补充关键信息，可配置流转状态必填属性。
5. 如需关联代码提交记录，在模板中启用 GitLab，并配置 Webhook。
6. 在项目管理中基于模板创建项目，并配置项目人员组成和基本信息。
7. 项目创建后，在项目中创建迭代，再维护需求、缺陷和任务等事务。
8. 项目成员按状态推进事务处理，并通过工作台查看个人待办、已办、上报和关注事项。
9. 如需展示研发数据，可在项目中配置仪表板，用于查看项目进度、需求分布或缺陷趋势。

> 注意：模板决定项目创建时的应用和字段规则。项目创建后，项目自身也可以维护应用设置，但调整前需要确认对已有项目数据和团队使用习惯的影响。

## 常见使用场景

### 创建一个新研发项目

先创建或选择合适的项目模板，再进入项目管理添加项目。创建项目时需要选择模板，并配置项目人员组成和基本信息。保存后，项目成员即可在项目中维护迭代、需求、缺陷和任务。

### 统一团队字段和流程

通过模板管理维护应用设置、属性设置和状态设置。属性用于控制事务需要填写哪些信息，状态用于控制事务如何流转。模板配置越清晰，项目成员在维护数据时越容易保持一致。

### 跟踪个人待处理事项

用户可以进入工作台查看“我的待办”。该列表展示处理人包含当前用户且状态未关闭的事务，适合日常跟进自己需要处理的研发事项。

### 按阶段推进研发工作

项目成员可以通过迭代管理阶段性工作。将需求、任务、缺陷或测试用例加入迭代后，可按迭代维度跟踪完成度。只有迭代中的事务都关闭后，迭代才算完成。

### 关联代码提交记录

在模板中启用 GitLab 后，系统会生成 Webhook URL。将该地址配置到 GitLab 或 Gitee 后，开发人员在提交代码时带上事务源码关键字，事务详情中即可生成对应提交记录。

### 查看研发数据展示

项目支持配置基于研发管理数据的仪表板。仪表板数据源来自系统配置中的数据仓库，适合展示项目进度、需求分布、缺陷趋势等数据。
