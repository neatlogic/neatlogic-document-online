# 工单处理
工单处理是指处理人对工单执行的操作处理过程。在工单处理页面中，操作分为工单维度和节点维度两大类：
- **工单维度操作**：包括修改上报内容、催办、取消/恢复工单、删除、关注、转报、关联重复事件和编辑表单。
- **节点维度操作**：包括开始、流转、撤回、回退、暂停、转交、表单、回复、子任务、评分等。

**注意：** 流程和服务的配置变更仅对新发起的工单生效，历史工单的配置不会自动更新。

## 1. 名词解释
### 1.1. 工单成员
- **上报人**：提交工单的用户。
- **代报人**：代替其他用户提交工单的用户。当提交工单时上报人非当前登录用户，当前登录用户即为代报人。
  ![](images/代报人.png)
  ![](images/代报人2.png)
- **处理人**：可执行工单步骤流转和回退操作的用户。
- **待处理人**：工单步骤已激活且分配给分组/角色，或同时分配给多个用户时，需执行“开始”操作完成接单后才能成为处理人的用户。
- **协助处理人**：除步骤处理人外，参与工单步骤处理活动的其他用户，包括子任务处理人和审批链审批人。
  ![](images/协助处理人_审批人.png)
- **代处理人**：用户可通过[个人设置](../../100.系统配置/1.用户和权限/个人设置.md)进行任务授权，将自己作为处理人或待处理人的工单授权给指定用户处理，被授权用户即为代处理人。
- **关注人**：关注工单的用户。
- **工单干系人**：非步骤处理人但需参与步骤处理的用户，如审批步骤的审批人、子任务处理人。

### 1.2. 工单状态
![](images/工单状态示例.png)
- **未提交**：工单尚未提交，仅可由上报人或代报人提交。
- **处理中**：工单存在未完成步骤，仅处理人和工单干系人可进行处理。
- **异常**：工单处理失败，无法正常继续处理。
- **已完成**：工单处理完毕。
- **已取消**：工单已被取消。
- **已评分**：工单处理完成且已完成评分。

### 1.3. 步骤状态
![](images/步骤状态示例.png)
- **待处理**：当前步骤节点尚未开始处理。
- **处理中**：当前步骤已开始处理但未完成。
- **异常**：当前步骤处理异常，例如条件分流节点未匹配到任何流转规则。
- **已完成**：步骤处理完毕。
- **已挂起**：步骤节点暂停，无法继续处理（例如撤回到上一步骤后当前步骤挂起）。

### 1.4. 变更步骤状态
![](images/变更步骤状态示例.png)
- **待处理**：变更步骤未开始处理，待处理人可执行取消、开始和回复操作。
- **进行中**：变更步骤正在处理中，处理人可执行取消、开始和回复操作。
- **已完成**：变更步骤处理完毕，处理人可对步骤进行回复操作。
- **已取消**：步骤直接取消，无法再执行操作。

## 2. 工单展示
**查看工单权限说明：**
1. 工单处理人和工单干系人查看工单时，跳转到**工单处理页**。
2. 非工单处理人且非工单干系人，但拥有工单所在**服务**及其**级联目录**查看权限的用户，跳转到**工单详情页**。
3. 非工单处理人且非工单干系人，且无工单所在**服务**或其**级联目录**查看权限的用户，无法查看工单内容并提示权限不足。

**工单详情tab排序说明：**

工单详情页面包含内容详情、节点信息、步骤日志、时间线、关联工单、重复事件、附件清单和上报历史等tab。tab顺序由[系统参数](../../100.系统配置/5.基础服务/基础服务.md)“processtask.tab.layout”控制：
- 参数值为空（"{}"）时，按系统默认顺序排序。
- 参数值为自定义JSON时，按自定义顺序展示。
- 参数值仅包含部分tab时，对应tab按参数值排序并置顶，其余tab默认不固定并按系统默认顺序排列。

![](images/工单tab固定.png)

**参数值示例：**
```json
{
    "position": "below",
    "layoutList": [
        {
            "key": "eoa",
            "top": false,
            "description": "电子签批"
        },
        {
            "key": "preNode",
            "top": false,
            "description": "前置步骤"
        },
        {
            "key": "autoexec",
            "top": true,
            "description": "自动化"
        }
    ]
}
```

- `position`：控制取消固定的tab位置（置于固定tab下方）。
- `top`：控制tab是否固定（"true"表示固定，"false"表示不固定）。
- `key`：与tab的对应关系如下表：

| key 值 | 描述 |
|-------|------|
| report | 上报内容 |
| collection | 工单集合 |
| dataconversion | 数据转换 |
| eoa | 电子签批 |
| subProcess | 子流程 |
| autoexec | 自动化 |
| automatic | 自动处理 |
| changecreate | 创建变更 |
| changehandle | 变更处理 |
| cmdbsync | 配置项同步 |
| createjob | 创建作业 |
| diagram | 架构设计 |
| taskConfigList | 子任务策略 |
| preNode | 前置步骤节点信息（eoa） |
| step | 步骤日志 |
| activity | 时间线 |
| relevance | 关联工单 |
| markrepeat | 重复事件 |
| file | 附件清单 |
| reportingHistory | 上报历史 |

### 2.1. 处理页和详情页
- **详情页**：仅展示工单基本信息和tab窗口，包括内容详情（表单信息）、节点信息（如电子签报）、步骤日志、时间线、上报历史。
  ![](images/工单详情页.png)
- **处理页**：除展示详情信息外，还显示当前可执行的处理操作，包括流转、回退、转交、暂停、撤回、转报、编辑表单、修改上报内容等。
  ![](images/工单处理页.png)

### 2.2. 工单信息
点击工单右侧的展开按钮，可查看工单详细信息，包括步骤信息、上报人及工单基本信息。步骤信息中包含当前步骤处理人、步骤状态、步骤开始和激活时间。
![](images/工单信息.png)

### 2.3. 步骤时效
步骤时效是提示处理人当前步骤剩余处理时间的倒计时功能。
![](images/工单时效效果图.png)

#### 2.3.1. 时效策略相关配置
1. 工单引用的流程需配置[时效策略](../流程管理/流程管理.md)，且待处理步骤需关联时效策略。
2. 发起工单的服务需配置有效服务窗口（即[服务窗口](../../100.系统配置/5.基础服务/服务窗口管理.md)需设置时间配置和排班）。

若满足条件1，步骤激活时工单满足时效策略生效条件，则时效策略立即生效；否则工单不显示时效策略。同时满足条件1和2时，显示正常倒计时；仅满足条件1但不满足条件2时，时效策略直接显示超时。

#### 2.3.2. 时效关联优先级
当时效策略关联优先级时，可为不同优先级设置不同处理时长，剩余时间会随优先级变化而动态调整。
![](images/步骤时效_关联优先级.gif)

#### 2.3.3. 剩余时间计算
流程时效策略的“时效”指服务窗口时间（工作时间）内的剩余可处理时间。若当前剩余服务窗口时间短于“时效”时长，则截止时间会顺延至下一天的服务窗口时间。

**示例：**
服务时间窗口为周一至周五的“8:00-12:00”和“14:00-17:00”，步骤激活时间为周五16:30，时效策略时长为60分钟，当天剩余服务时间仅30分钟。此时步骤截止时间将顺延至下周一早上8:30。

剩余时间的展示方式分为两种，由[系统参数](../../100.系统配置/5.基础服务/基础服务.md)“sla.time.display.mode”控制：
![](images/步骤时效_超时样式变量.png)

1. **自然日（naturalTime）**：剩余时间=截止时间-当前时间，步骤激活后持续倒计时直至超时。
   ![](images/步骤时效_自然日.png)

2. **工作日（workTime）**：剩余时间按时效策略时长倒计时，非工作时间内剩余时间静止，直至下一个工作时间恢复倒计时。
   ![](images/步骤时效_工作日.png)

若超时未处理，时效策略会变红并提示已超时时间。
![](images/步骤时效_已超时.png)

### 2.4. 任务列表
任务列表位于工单左侧，默认收起，显示处理人为当前登录用户的工单待处理步骤。
![](images/任务列表.png)

### 2.5. 内容详情
内容详情tab展示表单内容，详情页显示关联表单的主场景，处理页显示节点关联的表单场景。
![](images/内容详情.png)

### 2.6. 步骤日志
步骤日志展示步骤信息，包括处理人、时间、回复内容、子任务等。
[系统参数](../../100.系统配置/5.基础服务/基础服务.md)“processtask.step.list.show”控制步骤日志是否默认展开：参数值为1时默认展开，参数值为0时默认收起。
![](images/步骤日志.png)

### 2.7. 时间线
时间线tab展示所有工单操作的操作日志，默认按操作执行时间倒序排序。
![](images/时间线.png)

### 2.8. 上报历史
上报历史tab统计当前工单上报人提交的所有工单。例如当前工单上报人为admin，则上报历史会显示admin提交的所有工单。
![](images/上报历史.png)

### 2.9. 附件清单
附件清单显示上传到当前工单的所有附件，包括上报内容、回复、子任务、审批步骤等环节上传的附件。
![](images/附件清单.png)

### 2.10. 关联工单
关联工单分为两种情况：

1. **主动关联**
   允许转报的服务发起的工单，通过转报操作发起新工单后，两者互为关联工单。允许转报的工单还支持直接选择可转报服务下的工单作为关联工单。
   ![](images/关联工单.png)

2. **被动关联**
   通过转报发起的工单，若所在服务不允许转报，则仅有一个关联工单（即发起转报的原工单）。
   ![](images/被动关联的工单.png)

### 2.11. 查看流程图
工单支持查看完整流程图，通过连线状态可识别已完成节点，鼠标聚焦节点时可查看节点详情。

在弹窗中，点击编辑按钮可跳转到流程编辑页面（最新版流程配置），点击快照图标可打开新页签查看当前工单的流程配置。
![](images/查看流程图.png)

**连线、节点颜色与状态说明：**

| 颜色 | 节点状态 | 连线状态 |
|------|---------|----------|
| 绿色 | 已完成 | 已经过的路径 |
| 红色 | - | 不会经过的路径 |
| 蓝色 | 处理中 | - |
| 灰色 | 未激活 | 可能经过的路径 |

工单流程图快照支持修改节点配置。
![](images/工单流程图快照.png)

## 3. 工单操作
### 3.1. 工单维度的操作
#### 3.1.1. 修改上报内容
修改工单标题、优先级、上报描述、标签、关注人等内容，仅拥有修改上报权限的用户可操作，权限详情参考[流程管理](../流程管理/流程管理.md)-流程设置。
![](images/修改上报内容.png)
工单支持通过表单组件联动修改优先级，详情参考文档：[IT服务-场景](../IT服务-场景.md)-场景4。

#### 3.1.2. 催办
催办功能可与通知功能结合使用，[流程设置](../流程管理/流程管理.md)关联的通知模板中包含催办通知配置，发起催办时可通知指定用户。仅拥有催办权限的用户可操作，权限详情参考[流程管理](../流程管理/流程管理.md)-流程设置。
![](images/催办.png)

#### 3.1.3. 取消/恢复
取消或恢复工单，取消成功后工单状态变为已取消。仅拥有取消权限的用户可操作，权限详情参考[流程管理](../流程管理/流程管理.md)-流程设置。仅处理中或异常状态的工单支持取消。
![](images/取消.png)

#### 3.1.4. 删除工单
该操作位于工单中心的工单列表中，详情参考[工单中心](../工单中心/工单中心.md)-工单列表。

#### 3.1.5. 关注工单
工单页面右上角设有爱心图标，点击后当前用户即关注该工单，可在工单中心通过“与我相关”搜索条件快速筛选关注的工单。

#### 3.1.6. 转报
事件处理过程中引发其他事件时，可通过转报方式快速发起新事件单。

**转报权限**：当前工单所在服务需在配置中启用转报设置，详情参考[服务目录管理](../服务/服务目录管理.md)。
![](images/转报.gif)

允许转报的工单会显示关联工单tab，支持主动关联可转报服务下的任意工单，转报的工单也会显示在关联工单列表中。
![](images/关联工单.png)

#### 3.1.7. 批量关闭重复事件
该功能可批量关闭重复工单，仅限同一服务上报的工单。

在关联重复事件列表中，可添加并关联重复工单。
![](images/关联重复事件_选择工单.png)

多个工单关联为重复工单后，关联工单的重复事件列表会显示其他所有重复工单。当其中任意一个工单处理完成后，剩余重复工单自动转为已取消状态。
![](images/关联重复事件.png)

关联重复事件功能的启用状态由流程管理-[流程设置](../流程管理/流程管理.md)控制。

#### 3.1.8. 编辑表单
支持随时编辑表单内容，无论工单处于何种状态。编辑时回显表单主场景内容，保存时不校验表单必填项。仅关联表单的工单支持该功能，且需拥有[修改上报内容权限](../流程管理/流程管理.md)或[权限管理](../../100.系统配置/1.用户和权限/用户和权限.md)-IT服务-工单管理权限的用户可操作。
  ![](images/编辑表单按钮.png)
  ![](images/编辑表单效果.png)

#### 3.1.9. 工单转知识
当工单状态为已完成或已评分时，可将工单内容（包括上报内容、表单、回复等）转换为知识库文档。

**操作条件**：用户需同时满足以下条件：
1. 拥有知识库基础权限。
2. 是知识圈成员。

![](images/工单转知识.png)
![](images/工单转知识2.png)

### 3.2. 工单节点维度的操作
#### 3.2.1. 开始
工单节点状态为待处理时显示开始操作，开始后才能处理工单，仅待处理人有操作权限。
![](images/开始.png)

#### 3.2.2. 流转
流转到下一步，仅处理人有操作权限。
![](images/流转.png)

#### 3.2.3. 指派
工单节点的处理人分派策略包括五种：由前置步骤处理人指定、复制前置步骤处理人、表单值、分派器、自定义。配置详情参考文档[流程管理](../流程管理/流程管理.md)。

**由前置步骤处理人指定**效果如图：
![](images/由前置步骤处理人指定.png)

若分派策略无法匹配到用户，步骤会自动分派给异常处理人。
![](images/分派异常.png)

#### 3.2.4. 撤回
撤回到上一个处理节点，仅上一个节点的处理人有操作权限。
![](images/撤回.png)

#### 3.2.5. 回退
回退到前置步骤，仅处理人有操作权限，且节点需有回退线。若当前节点有多条回退线，仅激活过的回退线可执行回退。
![](images/回退.png)

回退到前置步骤后，前置步骤重新激活并分配处理人。根据[系统参数](../../100.系统配置/5.基础服务/基础服务.md)“processtask.workerpolicy.isonlyonceexecute”判断是重新执行分派策略，还是分配给步骤原处理人（步骤转交后处理人可能与分派策略对象不一致）。

#### 3.2.6. 转交
将当前步骤转交给其他用户处理，仅拥有节点转交权限的用户可操作，支持转交给用户、分组或角色。权限详情参考流程管理-[节点设置](../流程管理/流程管理.md)-权限设置。
![](images/转交.png)

转交操作分为两种模式：
- **保存并转交**：保存当前表单和回复内容后执行转交。
- **转交**：不保存当前表单和回复内容，直接执行转交。

#### 3.2.7. 子任务
处理步骤需多人协助时，可通过发起子任务实现。子任务完成策略包括“所有人完成”和“任意一人完成”，需在子任务策略管理页面配置。仅节点配置了子任务策略时才显示子任务窗口，详情参考[流程管理](../流程管理/流程管理.md)的节点设置。
![](images/子任务.png)

#### 3.2.8. 表单
工单内容详情回显当前节点引用的[表单场景](../流程管理/流程管理.md)。仅步骤处理人可编辑表单组件（场景设置为只读或禁用的组件除外）并暂存数据，工单流转后表单修改数据才会保存。
![](images/表单.png)

#### 3.2.9. 回复
1. **回复必填**
   回复分为必填和非必填两种模式，取决于流程[节点设置](../流程管理/流程管理.md)是否启用回复必填。
   ![](images/回复.png)

2. **附件**
   回复支持上传附件，点击回复按钮后附件保存到当前步骤。上传的附件可在当前步骤的步骤日志或附件列表中查看。

3. **关联知识库**
   支持输入关键字匹配包含该关键字的[知识库](../../98.知识库/新建知识文档.md)文档。

4. **回复模板**
   展开回复模板列表并选择模板后，回复框会自动填充模板内容。用户可用的回复模板包括个人模板和被授权使用的系统模板，详情参考[回复模板管理](../其他/其他.md)。
   ![](images/回复模板.png)

5. **回复功能的系统配置**
   ![](images/步骤回复系统参数.png)
   - [系统参数](../../100.系统配置/5.基础服务/基础服务.md)"processTaskStepEnableComment" 控制是否启用工单步骤回复功能：参数值为1时启用，参数值为0时禁用（仅可在流转时回复）。
     ![](images/步骤允许回复.png)
     ![](images/步骤不允许回复.png)
   - [系统参数](../../100.系统配置/5.基础服务/基础服务.md)"processTaskStepCommentEditorToolbarIsShow" 控制回复富文本框是否默认显示编辑器工具栏：参数值为1时默认显示，参数值为0时默认收起。

#### 3.2.10. 重新激活
重新激活操作支持重新执行自动执行失败的步骤，用户可在执行失败后修改工单内容并重跑，包括自动化、条件节点、数据转换节点。
![](images/重新激活.png)

#### 3.2.11. 评分
工单关联的流程启用评分设置后，当工单流转到已完成状态时可进行评分操作。评分维度与评分设置模板一致，详情参考 [流程管理](../流程管理/流程管理.md)-评分设置。
![](images/评分.png)

- **提交**：填写评分维度和内容后点击提交，评分操作完成，工单状态变为已评分。
- **回退**：若结束节点有连接到前置节点的回退线，未完成评分前可执行回退操作。

## 4. 工单通知场景
工单操作和工单超时支持通知功能，通知方式包括邮件通知、站内消息通知、微信通知等。

### 4.1. 工单维度操作的通知
执行[工单维度的操作](#31-工单维度的操作)后可通知指定对象，需在工单引用流程的流程设置-通知设置中配置通知模板。详情参考文档：[流程管理](../流程管理/流程管理.md)-流程设置。
![](images/流程通知策略.png)

### 4.2. 节点操作的通知
执行[节点维度的操作](#32-工单节点维度的操作)后可通知指定对象，需在工单流程对应节点的节点设置-通知设置中配置通知模板。详情参考文档：[流程管理](../流程管理/流程管理.md)-节点设置。
![](images/步骤通知策略.png)

### 4.3. 步骤时效超时通知
[步骤时效](#23-步骤时效)超时后可通知指定对象，需在工单流程的时效设置中配置超时通知策略。
![](images/超时通知策略.png)
