# 流程管理
流程管理用于设计工单从上报到完成的处理路径。

一条流程由流程图、流程节点、流程设置和节点设置组成。管理员可以根据业务场景组合人工处理、审批、自动化、外部调用、子流程、时效和评分等能力，让不同服务按照固定规则流转和处理。

本文以“先画流程，再配置节点，再补充时效、通知和评分”为主线，说明流程配置会影响工单处理中的哪些行为。

## 阅读路径

如果你是第一次配置流程，建议按“流程图 → 流程节点 → 流程设置 → 节点设置”的顺序阅读。如果你只需要调整处理人、权限、通知或按钮，直接查看“节点设置”。如果你要配置超时提醒或满意度评价，查看“时效设置”和“评分设置”。

**操作权限**
- 配置权限：系统配置-[用户管理](../../100.系统配置/1.用户和权限/用户管理.md)-授权-流程管理权限
- 配置人员：系统超级管理员

## 1. 流程图

流程图决定工单会经过哪些节点，以及在什么情况下继续向后流转或回退到前置节点。

绘制流程图时，需要先保证节点之间的连线合法，否则工单无法按预期进入后续处理。

连线规则如下：

- 开始节点不允许有连入线，结束节点不允许有连出线。
- 流程必须从起始节点（绿色）出发，在结束节点（红色）终止。开始与结束节点仅表示起止，无实际业务含义。
- 除起始和结束节点外，其他节点必须同时有连入和连出线，不能孤立存在。
- 开始节点后只能连接普通节点或创建变更节点。
- 节点拉线连接到后置节点时，显示为**实线**，代表流转路径；连接到前置节点时，显示为**虚线**，代表回退路径。

![](images/流程管理_绘制流程图.gif)

## 2. 流程节点

流程节点决定工单在某一步要做什么。

不同节点承担不同职责，有的需要人工处理，有的用于条件判断，有的负责调用自动化或外部接口。配置流程时，应先明确当前步骤解决的问题，再选择合适的节点类型。

流程节点包括分流、条件、通用、事件、变更创建、变更处理、自动处理、数据转换、自动化、定时等类型。

### 2.1. 分流节点

分流节点适合把工单按条件拆到不同处理路径。

它本身无需人工处理。工单流转到分流节点后，系统会判断条件，并激活匹配条件对应的后续节点。

![](images/流程管理_分流节点.png)

### 2.2. 条件节点

条件节点用于在流程中表达判断规则。

工单经过条件节点时，不需要人工处理。系统会根据配置的条件判断可走路径，并激活满足条件的后续节点。

![](images/流程管理_条件节点.png)

### 2.3. 通用节点

通用节点适合普通人工处理步骤。

处理人需要在该节点完成表单填写、回复、流转、回退、转交等操作。处理完成后，只能选择一条流转路径，并激活对应的后置节点。

![](images/流程管理_通用节点.png)

### 2.4. 变更创建节点

变更创建节点用于在工单流程中发起变更步骤。

它必须与变更处理节点配合使用，不能单独存在。适合在事件处理过程中需要进入变更管理的场景。

### 2.5. 变更处理节点

变更处理节点用于承接变更创建节点发起的变更处理。

该节点必须关联一个变更创建节点，且一个变更创建节点只能被引用一次。

![](images/流程管理_变更节点.png)

### 2.6. 事件节点

事件节点用于记录和处理事件类工单。

处理人可以在该节点中补充事件信息、关联事件类型或解决方案，并推进后续处理。

![](images/流程管理_事件节点.png)

### 2.7. 外部调用节点

外部调用节点适合在流程中自动调用第三方接口。

工单流转到该节点时，系统会调用已配置的集成接口，并根据返回结果判断节点是否执行成功。

![](images/流程管理_外部调用节点.png)
外部调用对象来自 [系统配置-集成管理](../../100.系统配置/3.数据和集成/集成管理.md) ，仅支持自定义类型的集成配置。<br>
参数值对象来自所引用的集成配置的输入参数，成功判断的自定义参数同样来源于该集成配置的输入参数。

### 2.8. 配置项同步节点

配置项同步节点用于把工单表单中的配置项变更同步到CMDB。

当表单中使用了“配置项修改”组件，并且需要在流程中正式写入配置项变更时，需要在节点设置中关联对应表单组件。

![](images/流程管理_配置项同步.png)

### 2.9. 自动化节点

自动化节点用于让工单流程自动发起作业。

当某一步处理可以通过脚本、组合工具或自动化服务完成时，可以使用自动化节点减少人工操作。自动化执行结果会影响节点是否继续流转。

![](images/流程管理_自动化节点.png)

自动化节点的作业详情为必填项。每个节点可添加一个或多个作业，支持引用组合工具或服务两种作业类型。

![](images/流程管理_自动化节点_作业详情.png)

#### 1. 引用组合工具

引用组合工具适合把自动化模块中已经编排好的能力接入工单流程。

配置时需关联自动化模块中已激活的[组合工具](../../5.自动化/工具/组合工具.md)，并完成参数映射。工单节点会根据映射值发起自动化作业。

自动化节点的目标参数与作业参数映射时，映射对象支持常量、表单普通组件、表单表格组件、工单信息和表达式。
- 常量：写入一个固定的值。
  ![](images/流程管理_自动化节点_常量映射.png)
- 表单普通组件：包括表格输入组件和表格选择组件，支持设置数据过滤条件。
  ![](images/流程管理_自动化节点_表单普通组件映射.png)
- 表单表格组件：包括表格输入组件和表格选择组件，支持设置数据过滤条件。
  ![](images/流程管理_自动化节点_表单表格组件映射.png)
- 工单信息：支持引用工单ID、步骤ID、步骤名称、标题、服务类型、上报内容、上报人等工单信息作为映射值。
  ![](images/流程管理_自动化节点_工单信息映射.png)
- 表达式：适用于文本类型参数的映射，可由自定义文本与表单组件的值拼接而成。
  ![](images/流程管理_自动化节点_表达式映射.png)

#### 2. 引用服务
引用服务适合由上报人或处理人在表单中选择自动化服务，再由流程节点按选择结果发起作业。

该方式需要关联表单中的自动化服务组件，组件数据来源于自动化模块的[服务目录](../../5.自动化/快捷服务/快捷服务.md)。

![](images/流程管理_自动化节点_自动化服务.png)

### 2.10. 定时节点

定时节点用于让工单在指定时间后自动继续流转。

该节点必须关联表单中的必填日期组件，无法人工处理。当系统时间达到设定的日期时间后，节点会自动流转至后置节点。

![](images/流程管理_定时节点.png)

## 3. 流程设置

流程设置作用于整张工单的生命周期。

如果某个能力与具体节点无关，而是影响工单整体，例如取消、修改上报内容、催办、通知、动作触发或重复事件标记，就应在流程设置中配置。

流程设置包括流程名称、关联表单、权限设置、通知设置、动作设置和标记重复事件。

![](images/流程管理_流程设置.png)

- 权限设置<br>
用于控制谁能对整张工单执行取消、修改上报内容和催办。未启用自定义时，取消和催办权限默认授予上报人，修改上报权限默认授予处理人。启用自定义后，仅授权对象拥有相应权限。<br>

  * 取消：取消工单，工单状态转为“已取消”，时效策略暂停。

  * 修改上报内容：修改标题、优先级、表单、描述、附件等工单信息。修改表单指修改上报节点的表单场景。
  
  * 催办：对工单进行催办。

- 通知设置<br>
用于配置工单维度操作触发后的消息提醒。启用后，需要引用[通知策略管理](../../100.系统配置/4.通知和订阅/通知策略管理.md)中的“IT服务-工单”模板；若不启用，则使用该模块的默认模板。

- 动作设置<br>
用于在工单操作发生时触发外部接口调用。外部接口配置来源于[集成管理](../../100.系统配置/3.数据和集成/集成管理.md)。
![](images/流程管理_流程设置_动作设置.gif)

- 标记重复事件<br>
用于处理多人重复上报同一问题的场景。关联重复工单后，其中一张工单处理完成时，其他重复工单可自动关闭。

## 4. 节点设置

节点设置用于配置某个具体节点的处理规则。

点击流程图中的节点图标，可打开对应节点的设置面板。这里的配置只影响当前流程中的当前节点；如果未启用自定义配置，则会引用[节点管理](节点管理.md)中的全局配置。

### 4.1. 表单场景

表单场景决定处理人在当前节点能看到或填写哪些表单内容。

表单场景分为默认场景和自定义场景。若未修改，节点默认使用表单的默认场景。

![](images/流程管理_节点设置_表单场景.png)

### 4.2. 权限设置

权限设置用于控制当前节点上哪些用户可以查看、转交、暂停或撤回。

节点权限包括查看节点信息、转交、暂停、撤回。

- 查看节点信息：查看步骤详情中对应节点的信息。若无权限，则无法查看。
- 转交：将工单当前节点的处理权限转交给其他用户。
- 暂停：暂停处理当前节点，工单挂起。
- 撤回：撤回到上一个处理节点。
  
![](images/流程管理_节点设置_权限设置.png)

启用开关表示在当前节点进行自定义授权，仅对当前流程的该节点有效。不启用则表示引用全局设置，即使用[节点设置](节点管理.md)中该类型节点的默认授权。工单权限判断时，局部权限优先级高于全局。

### 4.3. 通知设置

通知设置用于提醒当前节点相关人员关注工单变化。

通知设置默认引用全局配置。启用自定义后，需关联流程步骤模块的[通知策略](../../100.系统配置/4.通知和订阅/通知策略管理.md)，并可自定义通知策略的触发时机和参数映射。参数支持选择流程属性、表单组件，也支持输入常量。

### 4.4. 动作设置

动作设置用于在节点动作发生时调用外部接口。

节点动作设置与流程设置中的动作设置配置方式一致，区别在于触发条件不同。流程动作关注整张工单，节点动作关注某个步骤的处理过程。

流程动作触发条件说明：

| 动作 | 描述 |
| --- | --- |
| 上报 | 在工单上报页面完成“提交”操作。 |
| 取消工单 | 在工单详情页/处理页完成取消操作，工单状态变为“已取消”。 |
| 恢复工单 | 在工单详情页，对已取消的工单成功进行恢复操作，工单状态恢复到取消前的状态。 |
| 完成工单 | 工单流转到结束节点，工单状态变为“已完成”。 |
| 待评分 | 启用评分的工单流转到结束节点后，状态变为“待评分”。 |
| 评分 | 启用评分的工单完成评分提交后，状态变为“已评分”。 |
| 重新打开工单 | 启用评分且允许从结束节点回退到前置步骤的工单，在流转到结束节点并完成回退操作后，状态重新变为“处理中”。 |
| 标记重复事件 | 启用标记重复事件的工单，完成关联重复工单的操作。 |
| 删除工单 | 删除当前流程的工单。 |

节点动作触发条件说明：

| 动作 | 描述 |
| --- | --- |
| 步骤激活 | 工单流转到该步骤节点时立即触发。需在被激活的节点上配置。 |
| 分配异常 | 工单流转到某步骤，但按节点处理人分配策略未匹配到任何用户时触发。需在发生分配异常的节点上配置。 |
| 步骤开始 | 工单步骤激活后，执行开始操作时触发。需在开始的节点上配置。 |
| 步骤转交 | 转交工单当前步骤的处理人时触发。需在转交的节点上配置。 |
| 步骤成功 | 工单流转到下一个步骤，即前一步处理完成时触发。需在处理完成的节点上配置。 |
| 步骤回退 | 在有回退路径的节点发起回退时触发。需在发起回退的节点上配置。 |
| 步骤撤回 | 撤回到上一个节点时触发。需在发起撤回的节点上配置。 |
| 步骤暂停 | 暂停当前正在处理的节点时触发。需在暂停的节点上配置。 |
| 步骤恢复 | 恢复已暂停的步骤时触发。需在恢复暂停的节点上配置。 |
| 步骤失败 | 自动执行的步骤执行失败时触发。需在失败的节点上配置。 |
| 步骤催办 | 在处理中的步骤发起催办时触发。需在发起催办的节点上配置。 |
| 步骤回复 | 在处理中的步骤回复内容时触发。需在回复的节点上配置。 |
| 发起审批 | 处理审批节点时，发起审批链的操作。仅审批节点有此触发点。 |
| 激活审批步骤 | 审批节点发起审批链后，链中的审批步骤被激活时触发。仅审批节点有此触发点。 |
| 转交审批步骤 | 审批节点已发起审批链，转交当前正在处理的审批步骤处理人时触发。仅审批节点有此触发点。 |
| 同意审批步骤 | 审批节点已发起审批链，审批步骤处理人执行同意操作时触发。仅审批节点有此触发点。 |
| 驳回审批步骤 | 审批节点已发起审批链，审批步骤处理人执行驳回操作时触发。仅审批节点有此触发点。 |
| 审批成功 | 审批节点的审批链结束，节点处理人确认审批成功时触发。仅审批节点有此触发点。 |
| 审批失败 | 审批节点的审批链结束，节点处理人确认审批失败时触发。仅审批节点有此触发点。 |

### 4.5. 重审

重审适合“退回补充后，还要快速回到原审核节点”的场景。

启用重审后，回退后的处理人可以一键处理并流转回回退前的节点。启用重审的节点必须存在连入的回退线，否则该设置不生效。

![](images/流程管理_节点设置_重审.png)

### 4.6. 文案修改

文案修改用于让当前节点使用不同于全局配置的按钮、状态或页签名称。

未启用时，节点默认引用[节点管理](节点管理.md)中的全局设置。启用修改文案后，可自定义工单按钮、节点状态以及详情页页签标题。

![](images/流程管理_节点设置_修改文案.gif)

### 4.7. 自动开始

自动开始用于减少单人处理节点的接单动作。

当节点只分派给一个处理人时，启用后节点可自动开始处理，无需处理人手动点击开始。

### 4.8. 自动流转

自动流转适合不需要人工干预的过渡节点。

启用后，工单处理到该节点时，系统会自动完成流转，无需处理人手动操作。

### 4.9. 自动审批

自动审批用于避免同一处理人在连续审批节点中重复操作。

当当前节点分派的处理人包含上一个节点的处理人时，当前节点可自动完成处理。该功能由[系统参数](../../100.系统配置/5.基础服务/基础服务.md)“processtask.step.autoapproval.show”控制，参数值为 1 时，流程节点可使用自动审批功能；参数值为 0 时，该功能隐藏。

配置条件：
1. 在需要自动审批的节点启用自动审批配置。
![](images/流程管理_节点设置_自动审批.png)
2. 在启用自动审批的节点及其上一个节点，添加相同的标签（例如“审批”）。
![](images/流程管理_节点设置_自动审批标签.png)

### 4.10. 回复必填

回复必填用于确保处理人在流转前留下处理说明。

启用后，工单处理到该节点时，系统会校验回复内容是否为空。若未填写回复，节点无法流转。

### 4.11. 默认回复

默认回复用于给处理人预填常用处理说明。

节点可配置默认回复模板，模板来源于[回复模板管理](../其他/回复模板管理.md)。处理工单对应节点时，回复框会自动填充模板内容。默认回复生效需满足条件：处理人拥有该回复模板的权限。

![](images/流程管理_节点设置_回复模板.png)

### 4.12. 创建子任务

创建子任务用于在当前节点中引入多人协作。

配置了[子任务策略](../其他/子任务策略管理.md)的节点，在工单处理时支持添加子任务。子任务的处理人数、完成策略和快捷回复按钮由子任务策略控制。

![](images/流程管理_节点设置_创建子任务.gif)

### 4.13. 分配处理人

分配处理人决定工单到达当前节点后由谁处理。

节点分配处理人的策略包括前置步骤处理人指定、复制前置步骤处理人、表单值、分派器和自定义分派。匹配方式支持全部匹配和顺序匹配。

- 全部匹配：将匹配成功的所有策略分配到的用户全部作为处理人。
- 顺序匹配：按顺序匹配第一个成功的策略，并将其分配到的用户作为处理人。

#### 4.13.1. 由前置步骤处理人指定

由前置步骤处理人指定适合后续处理人需要由上一节点现场判断的场景。

前置步骤流转时，可指定当前节点的处理人。此策略需关联前置步骤。

![](images/流程管理_前置步骤指派.png)
- 若前置步骤未设置条件路径，则流转时默认显示指派操作。

- 若设置了条件路径，则仅当选择该条件路径时，才显示指派操作。
![](images/流程管理_前置步骤指派_条件路径.png)

指派目标：指派时可选择的对象类型，包括用户、分组和角色。若仅选择用户，则指派对象下拉框只显示用户。
指派范围：指派时可选择的具体对象范围，可选对象类型根据指派目标展示。
- 指派范围为空，则不限制范围。
- 若指派目标是角色或分组，则指派时的分组或角色需与指派范围一致。
- 选择指派范围后，可选择的用户对象为指派范围的并集，包括指定的用户、分组成员、角色成员，以及角色关联的分组成员。如下图所示。
![](images/流程管理_前置步骤指派_指派范围.png)
![](images/流程管理_前置步骤指派_指派.png)
   
#### 4.13.2. 复制前置步骤处理人

复制前置步骤处理人适合连续处理需要由同一人跟进的场景。

工单流转至当前节点时，系统会复制关联前置节点的处理人作为本节点处理人。此策略需关联前置步骤。

#### 4.13.3. 表单值

表单值分派适合在上报或处理过程中由表单字段决定处理人的场景。

该策略需关联用于映射的表单组件，支持用户选择器、下拉框和文本框组件。

- 引用下拉框组件时，其“值”的映射对象支持用户的 uuid 和 userid。
- 引用文本框组件时，输入值需匹配用户的 userid 或 uuid。
![](images/流程管理_表单值分配处理人.png)

#### 4.13.4. 分派器

分派器适合处理人需要按组织、工作量或配置项关系自动计算的场景。

配置时需关联分派器。工单流转至节点时，系统会根据分派器逻辑自动指定处理人。

| 分派器类型 | 描述 | 图示 |
| --- | --- | --- |
| 处理人领导分派器 | 根据前置步骤的处理人，查找其所在的所有分组的所有领导，并将匹配到的所有用户指定为待处理人。 | <img src="images/流程管理_处理人领导分派器.png" width="800"> |
| 分组领导分派器 | 查找指定分组的全部领导，并将匹配到的所有用户指定为待处理人。 | <img src="images/流程管理_分组领导分派器.png" width="800"> |
| 根据工作量分配处理人 | 在指定分组中，将任务分配给待处理工单数量最少的成员。若最少数量对应多个成员，则全部匹配为待处理人。 | <img src="images/流程管理_根据工作量分配处理人.png" width="800"> |
| 上报人领导分派器 | 查找上报人所在的所有分组的全部领导，并将匹配到的所有用户指定为待处理人。 | <img src="images/流程管理_上报人领导分派器.png" width="800"> |
| CMDB分派器 | 支持通过模型或视图的属性与表单组件进行映射，将匹配到的用户、分组或角色作为节点待处理人。<br>配置项包括数据类型、数据来源、匹配映射、处理人和优先级。匹配映射的关键在于：[表单](../../100.系统配置/3.数据和集成/表单管理.md)组件必须引用[配置项矩阵](../../100.系统配置/3.数据和集成/矩阵管理.md)，且该矩阵引用的配置模型需与匹配映射的属性为同一模型。<br>注意：当匹配到的配置项不唯一，或匹配到唯一对象但系统中不存在该对象时，CMDB分派器无法生效，节点将自动分配给异常处理人。 | <img src="images/流程管理_CMDB分派器-示例.png" width="800"> |

#### 4.13.5. 自定义

自定义分派适合处理人范围固定、不需要动态计算的节点。

配置时可直接选择分派对象，支持上报人、代报人、用户、角色和分组。

![](images/流程管理_节点设置_分配处理人.gif)

### 4.14. 异常处理人

异常处理人用于兜底处理分派失败的工单。

当节点分配处理人出现异常，例如分派策略没有匹配到任何用户时，节点会自动分配给此处指定的异常处理人。该字段为必填项。
  
## 5. 时效设置

时效设置用于限制工单步骤的处理时间。

当某些步骤需要按服务窗口计算剩余处理时间，或需要超时提醒时，可以在流程中配置时效策略。工单流转到关联步骤并满足生效条件后，时效策略会开始计算。

添加时效策略步骤：点击“添加时效策略” → 配置时效 → 保存。

![](images/流程管理_时效设置.gif)

关联步骤用于选择时效策略作用于哪些节点。若关联多个步骤，步骤耗时详情请参考计算规则提示。当工单流转到关联步骤并满足生效条件时，时效即被激活。

![](images/流程管理_时效计算规则.png)

## 6. 评分设置

评分设置用于在工单完成后收集服务反馈。

如果服务需要满意度评价或质量评价，可以在流程中启用评分，并关联[评分模板](../其他/评分模板管理.md)。工单完成后，用户可按模板维度进行评分。

评分设置步骤：启用评分 → 选择评分模板 → 配置自动评分。

流程启用评分设置后，结束节点支持拉取回退线到前置节点；未启用评分时，结束节点不支持回退。
![](images/流程管理_评分设置.png)

自动评分用于处理用户长期未评分的工单。若未在指定时间段内完成评分，系统将自动给予好评。

![](images/流程管理_评分设置_自动评分.png)
