# 服务目录管理
服务目录管理用于搭建用户上报工单时看到的服务入口。

目录决定服务的层级结构，服务决定用户可以上报什么工单、走哪个流程、谁能上报和谁能查看。配置完成后，用户在[工单上报](工单上报.md)页面选择服务，系统会按服务关联的流程、表单、优先级和权限创建工单。

本文主要说明目录与服务的配置边界，以及服务中的优先级、标题模板、转报和展示规则。

## 阅读路径

可根据当前要解决的问题选择阅读入口。

- 如果需要整理上报入口，阅读“目录”。
- 如果需要创建可上报工单的服务，阅读“服务”和“添加服务”。
- 如果用户看不到服务或工单，阅读“数据权限”。
- 如果需要从一张工单转出另一张工单，阅读“转报设置”。

## 权限说明

服务目录的权限分为操作权限和数据权限。

操作权限控制谁能维护目录和服务；数据权限控制普通用户能不能上报服务、查看服务下产生的工单。

### 操作权限

- 权限配置：系统配置-[用户管理](../../100.系统配置/1.用户和权限/用户管理.md)-授权-服务目录管理权限
- 配置人员：系统超级管理员

### 数据权限

| 权限名称 | 描述 | 配置说明 |
|:------------:|:------------:|:--------:|
|上报授权|访问目录及其服务，上报工单|当前登录人必须有“目录-服务”全路径各级的授权，才能通过当前目录下的服务创建工单。|
|查看授权|查看目录下服务上报的工单|当前登录人必须有“目录-服务”全路径各级的授权，才能查看通过当前目录下服务创建的工单。|

## 目录

目录用于组织服务的层级。

当服务数量较多时，可以通过目录把服务按业务域、系统、部门或处理场景归类。目录支持添加、编辑、删除和权限配置。

### 添加目录

添加目录用于创建新的服务分组。目录创建后，可在其下继续添加子目录或服务。

![](IMAGES/服务目录管理_添加目录.png)

### 编辑目录

编辑目录用于调整目录名称、状态或权限信息。目录状态会影响其下服务在电脑端和移动端是否可见。

![](IMAGES/服务目录管理_编辑目录.png)

### 删除目录

- **可删除状态**：目录下无服务，且不存在被引用的服务时，可直接删除。
![](IMAGES/服务目录管理_删除目录_可删除.png)
- **不可删除状态**：目录下存在服务或被引用时，无法删除。
![](IMAGES/服务目录管理_删除目录_不可删除.png)

## 服务

服务是用户发起工单的实际入口。

每个服务都会关联流程、服务类型、服务窗口、优先级和权限等配置。只有拥有服务上报权限的用户，才能通过该服务上报工单；拥有查看权限的用户，才能查看该服务创建的工单。
  
### 添加服务

添加服务时，需要先明确这项服务解决什么问题、交给哪个流程处理，以及哪些用户能使用。

常见配置项如下：

- **工作流**：关联的[流程](../流程管理/流程管理.md)
- **标题模板**：定义工单标题生成规则
- **优先级**：关联的[优先级配置](../其他/优先级管理.md)
- **服务窗口**：关联的[服务窗口](../../100.系统配置/5.基础服务/服务窗口管理.md)
- **服务类型**：关联的[服务类型](../服务/服务类型管理.md)
- **上报权限**：谁可以使用该服务上报工单
- **查看权限**：谁可以查看该服务创建的工单
- **转报设置**：配置工单转报规则
- **使用范围**：指定服务在PC端或移动端的可见性

![](IMAGES/服务目录管理_添加服务.png)

### 优先级配置

优先级配置决定工单是否有优先级，以及用户在上报、查看和处理工单时能否看到优先级。

服务中的优先级状态和显示配置会影响工单页面的展示效果：

- **优先级未激活**：通过该服务上报的工单无优先级数据。
  ![](images/服务_优先级未启用效果.png)

- **优先级激活，但设置为隐藏**：工单上报页、详情页和处理页均不显示优先级，工单优先级取默认值。此情况下仍支持通过表单组件触发联动修改优先级值。
  ![](images/服务_优先级不显示.png)
  ![](images/工单_优先级隐藏效果.png)

- **优先级激活且不隐藏**：工单上报页、详情页和处理页均正常显示优先级。
  ![](images/服务_优先级显示.png)
  ![](images/工单_优先级显示.png)

### 标题模板

标题模板用于统一工单标题格式。

模板支持常量和变量。用户上报工单时，系统会根据模板自动生成工单标题，减少手工填写差异，也方便后续在[工单中心](../工单中心/工单中心.md)中搜索和识别。

![](images/服务_标题模板.png)

### 转报设置

转报设置用于处理“当前工单还需要发起另一张关联工单”的场景。

启用“允许转报”后，该服务下的工单可以通过指定目标服务发起新的转报工单。执行转报的用户必须属于转报授权对象。

转报配置包含以下要素：
- **转报关系类型**：一个服务可关联多个[关系类型](../其他/关系类型管理.md)
- **转报目标服务**：指定转报时使用的目标服务
- **转报授权对象**：允许执行转报操作的用户或角色
  
![](IMAGES/服务目录管理_转报设置.png)

### 服务在电脑端和移动端的展示规则

服务是否展示，由目录状态、服务状态和使用范围共同决定。

如果用户在电脑端或移动端看不到某个服务，可以先按下表检查目录是否激活、服务是否激活，以及服务使用范围是否包含当前端。

| 目录激活状态 | 服务激活状态 | 使用范围 | 电脑端展示 | 移动端展示 |
|:------------:|:------------:|:--------:|:--------:|:----------:|
| 已激活 | 已激活 | 所有 | 是 | 是 |
| 已激活 | 未激活 | 所有 | 否 | 否 |
| 未激活 | 已激活 | 所有 | 否 | 否 |
| 未激活 | 未激活 | 所有 | 否 | 否 |
| 已激活 | 已激活 | 手机端 | 否 | 是 |
| 已激活 | 已激活 | 电脑端 | 是 | 否 |
