# IT服务入门

IT服务模块用于把用户的服务请求、事件处理、审批流转和执行记录沉淀为可跟踪的工单。它的核心价值是：让用户通过服务目录提交需求，让处理人按流程协同处理，让管理者通过分类、权限、时效、通知和评分等配置统一服务规范。

## 模块定位

IT服务主要围绕“服务”和“工单”展开：

1. **服务目录**：面向用户提供可上报的服务入口，例如故障报修、权限申请、资源变更、系统咨询等。
2. **流程管理**：定义工单提交后的处理路径，包括处理节点、审批节点、自动化节点、条件分流、子流程、时效和通知。
3. **工单中心**：集中查看、搜索和管理不同状态、不同分类的工单。
4. **工单处理**：处理人根据当前节点执行开始、流转、回退、转交、回复、子任务、评分等操作。
5. **事件管理**：通过事件类型和解决方案沉淀常见问题的分类与处理经验。
6. **基础配置**：通过服务类型、优先级、回复模板、评分模板、子任务策略、关系类型等配置提升工单管理的一致性和效率。

## 核心流程

一个典型 IT 服务从配置到使用通常按以下链路运行：

1. 管理员准备表单，用来收集用户上报时需要填写的信息。
2. 管理员设计流程，配置节点、处理人、权限、通知、时效和评分规则。
3. 管理员创建服务目录和服务，将服务关联到对应流程，并设置上报权限、查看权限、优先级、服务类型和服务窗口。
4. 用户在服务目录或快捷入口中选择服务并提交工单。
5. 处理人在工单处理页按流程处理、回复、转交、回退、添加子任务或发起转报。
6. 工单完成后，可根据流程设置进行评分，并在工单中心持续检索和追踪历史记录。

> 注意：流程、服务、权限、通知、时效等配置通常只影响新发起的工单；历史工单不会自动同步最新配置。

## 功能地图

| 功能区域 | 主要作用 | 适用场景 |
|:--|:--|:--|
| 服务目录管理 | 维护服务层级、服务入口、上报权限和查看权限 | 用户需要按目录选择服务并提交工单 |
| 服务类型管理 | 定义服务分类、工单号前缀和工单号规则 | 需要按请求、事件、变更等类型管理工单编号 |
| 流程管理 | 编排工单处理步骤、节点权限、动作、通知、时效和评分 | 需要让不同服务按不同处理路径流转 |
| 节点管理 | 管理节点权限、按钮、状态和其他映射 | 需要统一不同节点的展示和操作规则 |
| 工单上报 | 支持单个工单上报、草稿暂存和批量上报 | 用户提交服务请求或批量导入工单 |
| 工单中心 | 提供工单分类、搜索、列表和卡片视图 | 需要集中查询、跟踪和管理工单 |
| 工单处理 | 执行工单级和节点级处理动作 | 处理人推进工单、协作处理和记录过程 |
| 事件类型管理 | 维护事件分类及分类授权 | 需要按事件类型归档和控制可选范围 |
| 解决方案管理 | 沉淀事件解决方案并关联事件类型 | 处理常见事件时复用经验 |
| 优先级管理 | 定义工单优先级及排序 | 需要按紧急程度或影响程度区分处理顺序 |
| 子任务策略管理 | 定义子任务人数、完成策略和快捷回复按钮 | 一个节点需要拆分多人协作任务 |
| 回复模板管理 | 管理高频回复内容 | 处理人需要快速填写标准回复 |
| 评分模板管理 | 定义评分维度和描述 | 工单完成后需要用户评价服务质量 |
| 关系类型管理 | 定义工单之间的关联关系 | 需要表达转报、重复、关联等工单关系 |

## 入门配置顺序

首次使用 IT 服务模块时，建议先完成最小可用配置：

1. 配置**服务类型**，确保工单提交后可以生成符合规则的工单号。
2. 准备**表单**，明确用户上报时需要填写哪些信息。
3. 创建**流程**，至少包含上报节点和处理节点，并配置处理人和流转动作。
4. 创建**服务目录**和**服务**，将服务关联到流程，并开放上报权限。
5. 使用普通用户账号提交一张测试工单，验证上报内容、权限、处理人、通知和流转是否符合预期。
6. 根据实际管理要求补充优先级、服务窗口、评分模板、回复模板、子任务策略和转报设置。

## 常见使用场景

### 用户提交服务请求

用户通过服务目录或快捷入口选择服务，填写标题、表单内容、描述、附件等信息并提交。若暂时不提交，可先保存为草稿，后续在工单中心继续编辑。

### 处理人推进工单

处理人进入工单处理页后，根据当前节点状态执行开始、回复、流转、回退、转交、暂停、子任务、评分等操作。工单详情中可查看内容详情、步骤日志、时间线、附件、关联工单和流程图。

### 管理员搭建服务目录

管理员先按业务场景规划目录层级，再添加具体服务。服务需要关联流程，并配置上报权限、查看权限、优先级、服务窗口、服务类型、标题模板、转报设置和使用范围。

### 事件处理经验复用

管理员可维护事件类型和解决方案。处理事件时，用户按事件类型选择分类后，可快速匹配或查看对应解决方案，减少重复排查成本。
