# 数据源

数据源用于维护非本地数据库的连接配置。当数据仓库需要连接外部数据库执行查询脚本时，可以先在数据源中统一维护连接参数，再在[数据仓库](数据仓库.md)的数据源配置中引用。

对新手来说，可以把数据源理解为“数据库连接信息”的集中管理位置。它只负责保存连接地址、账号、密码等连接参数，并验证系统是否能够连通目标数据库；它不负责维护业务数据，也不直接作为表单组件的数据来源。

## 阅读路径

可根据当前要解决的问题选择阅读入口。

- 如果需要维护外部数据库连接，阅读“数据源管理”。
- 如果不确定连接参数如何填写，阅读“配置示例”。
- 如果需要确认系统能否访问目标数据库，阅读“测试连接”。
- 如果数据仓库引用数据源失败，可先回到“测试连接”确认连接是否正常。

## 权限

**操作权限**
- 配置：系统配置-[用户管理](../1.用户和权限/用户管理.md)-授权-数据仓库管理权限
- 包含操作：新增、编辑、删除和测试数据源连接
- 配置人员：系统超级管理员

## 数据源管理

数据源列表用于集中查看系统中已经维护的外部数据库连接。当需要新增数据库连接、调整连接参数或清理无效连接时，可以在这里统一维护。

维护数据源前，应确认目标数据库允许当前系统访问，并确认连接账号具备后续查询所需的权限。对于生产库或核心业务库，建议使用只读账号，避免连接账号拥有过大的写入或管理权限。

## 配置示例

配置数据源时，需要根据数据库类型填写连接地址、端口、库名、账号和密码。不同数据库类型的连接参数可能不同，应以目标数据库的实际连接方式为准。

以下为 MySQL 数据源配置示例：

```json
{
  "password": "xxxxxxxx",
  "driverClassName": "com.mysql.jdbc.Driver",
  "user": "root",
  "url": "jdbc:mysql://192.168.0.1:3306/neatlogic_develop?characterEncoding=UTF-8"
}
```

保存前建议先测试连接，确认连接参数无误。这样可以避免后续在数据仓库中引用该数据源时，才发现地址、账号或网络访问存在问题。

## 测试连接

测试连接用于验证系统是否可以正常访问目标数据库。测试失败时，可以优先检查网络连通性、数据库地址、端口、账号密码和数据库权限；如果连接参数正确但仍无法访问，还需要确认目标数据库是否限制了访问来源。
