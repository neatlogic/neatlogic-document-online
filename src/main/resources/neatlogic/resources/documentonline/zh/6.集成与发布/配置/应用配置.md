# 应用配置

应用配置用于维护应用发布所需的流水线、模块、环境、执行器、实例和授权规则，是集成与发布模块的核心配置页面。

应用和模块数据来源于配置管理，分别对应“应用系统”和“应用模块”模型；环境数据来源于全局属性。应用包含模块，模块关联环境，环境中包含一个或多个实例对象。

应用层用于配置通用发布流水线。模块层和环境层默认继承上一级流水线，也可以根据实际发布差异重定义阶段、工具、参数和执行目标等配置。

## 阅读路径

可根据当前要完成的配置选择阅读入口。

- 如果需要创建或维护发布流水线，阅读“流水线”和“编辑流水线”。
- 如果需要维护应用信息、模块和发布通知，阅读“应用层”。
- 如果需要配置应用、环境、场景或版本制品的使用范围，阅读“授权”。
- 如果需要为模块配置环境、执行器或流水线差异，阅读“模块层”。
- 如果需要维护数据库、配置变量、实例和蓝绿发布顺序，阅读“环境层”。
- 如果需要通过代码提交触发发布作业，阅读“持续集成”。
- 如果需要批量编排当前应用的发布作业，阅读“应用超级流水线”。

## 权限

**操作权限**

- 配置：系统配置-[用户管理](../../100.系统配置/1.用户和权限/用户管理.md)-授权-应用配置维护权限
- 包含操作：访问应用配置页面，并对已获得数据权限的应用执行配置操作
- 配置人员：系统超级管理员

**操作权限**

- 配置：系统配置-[用户管理](../../100.系统配置/1.用户和权限/用户管理.md)-授权-自动发布管理权限
- 包含操作：执行集成与发布模块全部页面的资源和操作，不受应用数据范围限制
- 配置人员：系统超级管理员

**数据权限**

- 配置：应用配置-应用层-授权
- 包含操作：查看配置、编辑配置、执行、权限、版本和制品管理、超级流水线、环境权限和场景权限
- 配置人员：拥有当前应用“权限”权限的用户

> 新增应用时，系统会自动为创建人添加应用授权，创建人默认拥有该应用的全部数据权限。

## 流水线
流水线是发布脚本模板。与[组合工具](../../5.自动化/工具/组合工具.md)类似，流水线由阶段组、阶段、工具、作业参数、场景、连接协议和执行用户等内容组成。

应用流水线支持两种配置方式：引用组合工具模板和导入流水线配置。

### 引用模板
引用模板的流程为：选择流水线模板、选择工具、编辑流水线、配置预置参数、配置场景、配置执行用户和配置执行器。

![](images/应用配置_添加流水线_引用模板.gif)

1. 流水线工具来源于自动化-[组合工具](../../5.自动化/工具/组合工具.md)。
2. 选择组合工具后，系统会回显组合工具中的阶段、工具和参数配置。应用层支持新增、删除和修改阶段、工具及参数；模块层和环境层需要先启用重定义，才能修改继承的配置。
3. 如果工具关联了预置参数集，“预置参数”步骤会回显当前流水线引用的全部预置参数集，并支持重新配置参数映射值。
![](images/应用配置_流水线_预置参数集.png)
4. 场景用于从整条流水线中选择部分阶段作为发布场景，供发布作业使用。流水线必须至少配置一个场景。
5. 执行用户用于设置目标机器的连接协议和执行用户。
6. 执行器是指 runner 执行器。详细配置可参考[Tagent服务](../../5.自动化/Tagent服务/Tagent服务.md)。

### 导入流水线配置
导入流水线适用于在不同环境或租户之间迁移应用流水线配置。

可以先从其他环境导出应用流水线，再导入到当前环境中同名应用。导入时，系统会同时导入依赖配置；如果本地存在同名依赖配置，可以选择是否覆盖。

## 应用层
应用层用于维护应用的通用发布配置，包括流水线、应用信息、模块、通知、授权、持续集成和应用超级流水线。

![](images/应用配置_添加应用.png)

### 编辑流水线
应用层可以编辑流水线中的阶段、工具、场景、执行账号、阶段组和预置参数等配置。

修改流水线后，可以暂存为草稿。再次编辑时，可以选择继续编辑草稿。

![](images/应用配置_应用层_保存为草稿.png)

![](images/应用配置_流水线草稿.png)

### 编辑应用、添加模块
应用层支持编辑应用信息，并添加子模块。

![](images/应用配置_管理应用和模块信息.png)

### 通知
通知用于配置发布失败后的通知策略。通知策略来源于系统配置-[通知策略管理](../../100.系统配置/4.通知和订阅/通知策略管理.md)。

![](images/应用配置_通知.png)

### 授权
应用层可以对应用、环境和场景进行授权。

应用未配置授权时，所有用户都可以看到该应用配置。配置授权后，用户需要同时满足系统权限和应用数据权限，才能查看或操作对应应用。

![](images/应用配置_应用授权.png)

- **查看配置**：控制应用是否显示在应用列表中。拥有查看配置权限的用户，可以查看该应用及其下级模块、环境配置。
![](images/应用配置_授权_有查看配置权限.png)

缺少查看配置权限时，应用列表不会显示该应用。
![](images/应用配置_授权_无查看配置权限.png)

- **编辑配置**：控制当前应用中除“权限”外的配置编辑能力。编辑配置的前提是拥有查看配置权限。

拥有编辑配置权限后，可以编辑应用配置；缺少该权限时，编辑操作会隐藏或禁用。
![](images/应用配置_授权_无编辑配置权限.png)

- **执行**：控制用户是否可以在一键发布页面发起该应用的作业。执行权限的前提是拥有查看配置权限。

缺少应用执行权限时，无法在一键发布页面发起该应用的作业。
![](images/应用配置_授权_无执行权限.png)

- **权限**：控制用户是否可以维护当前应用的授权配置。
![](images/应用配置_授权_权限.png)

缺少“权限”权限时，授权列表为只读状态。
![](images/应用配置_授权_无权限列表权限.png)

- **版本和制品管理**：控制用户是否可以在版本中心管理该应用的版本和制品。该权限的前提是拥有查看配置权限。
![](images/应用配置_授权_无版本和制品权限.png)

- **超级流水线**：控制用户是否可以在应用配置页面维护该应用的超级流水线。该权限的前提是拥有查看配置权限。
![](images/应用配置_授权_有超级流水线权限.png)
![](images/应用配置_授权_无超级流水线权限.png)

- **环境权限**：控制用户是否可以编辑对应环境的配置；发起发布作业时，也控制用户是否可以选择该环境。
![](images/应用配置_授权_无环境权限.png)

- **场景权限**：控制用户在发起发布作业时是否可以选择对应场景。
![](images/应用配置_授权_无场景权限.png)

### 持续集成
持续集成用于在特定事件发生时触发发布作业，支持添加、编辑、删除和搜索配置。

![](images/应用配置_持续集成.png)

添加持续集成前，需要在代码仓库的管理员设置中启用 Webhook 向本地网络发送请求。

以GitLab为例：

路径：Admin Area → Settings → Network → Outbound requests。

操作：勾选 `Allow requests to the local network from system hooks`，并添加允许访问的 IP 或 CIDR 范围，例如 `192.168.1.0/24`。

![](images/应用配置_持续集成_gitlab配置.png)

随后，在系统参数中配置 `gitlabWebHookCallbackHost`，用于指定 GitLab Webhook 回调主机地址。

![](images/应用配置_持续集成_回调主机地址配置.png)

### 应用超级流水线
应用超级流水线是当前应用的批量发布作业模板，支持添加、编辑、删除、发起批量作业和查看作业列表。

![](images/应用配置_超级流水线.gif)

## 模块层
模块层用于维护模块级发布差异，支持编辑模块信息、配置执行器、关联环境、重定义流水线、复制配置和清空配置。

### 编辑模块
在当前模块层点击编辑，修改模块信息并保存即可。

![](images/应用配置_模块层_编辑模块.png)

### 包含环境
模块包含环境有以下两种来源：

**模块层添加环境**

![](images/应用配置_模块层_添加环境.png)

**模块关联应用实例所属环境**

模块未关联环境或实例时，环境和关联实例均为空。

![](images/应用配置_模块层_无环境和实例.png)

在模块数据中添加关联实例后，如果实例的“应用环境”属性存在数据，模块会自动包含该实例所属的应用环境。

![](images/应用配置_模块层_添加关联实例.png)

![](images/应用配置_模块层_更新实例所属环境.png)

### 重定义流水线
模块层可以在应用层流水线基础上重定义配置。

支持重载或禁用阶段。阶段重载后，可以添加、删除和修改工具，也可以重定义预置参数集、执行账号和阶段组。

![](images/应用配置_模块层重定向.gif)

### 复制配置
可以将当前模块的流水线配置复制到同一应用下其他未重定义的模块，也可以新增模块后复制当前模块配置。

![](images/应用配置_复制模块配置.gif)

### 执行器组分配
远程在实例上执行脚本时，使用模块层分配的 runner 执行器。

模块层未分配执行器时，无法发起发布作业。

![](images/应用配置_模块层_执行器组分配.png)

### 清空配置
清空当前模块已重定义的配置后，模块会恢复使用应用层的默认配置。

![](images/应用配置_模块层_清空配置.png)

## 环境层
选中应用模块下关联的环境后，页面会切换到环境配置。

环境层支持配置环境 DB 配置、配置变量、变量实例差异和实例列表。

![](images/应用配置_环境层.png)

编辑环境数据时，需要同时拥有应用的编辑配置权限和对应环境权限。

![](images/应用配置_环境层_相关权限.png)

### 重定义流水线
环境层可以在模块层流水线基础上重定义配置。

支持重载或禁用阶段。阶段重载后，可以添加、删除和修改工具，也可以重定义预置参数集、执行账号和阶段组。

### 删除环境
删除环境是解除当前模块与环境之间的关联关系，不会删除环境数据。

环境数据来源于[全局属性](../../3.配置管理/系统管理/全局属性管理.md)中的“应用环境”属性。

![](images/应用配置_删除环境.png)

### DB 配置

DB 配置支持添加、编辑和删除。

数据库对象来源于资产清单中的数据库实例；账号来源于已选数据库实例配置的账号。

![](images/应用配置_环境层_添加DB配置.png)

添加 DB 配置时，如果数据库下拉框缺少所需数据，可以快速添加数据库及其账号。

![](images/应用配置_环境层_快速添加数据库.png)

保存 DB 配置时，如果出现下图提示，表示该数据库已被同一应用下的其他模块引用。此限制与[全局属性](../../3.配置管理/系统管理/全局属性管理.md)中“应用环境”的单选配置有关。

![](images/应用配置_环境层_保存DB配置失败.png)

### 配置文件适配
配置文件适配用于维护环境公共变量。环境包含的实例可以重定义变量值。

**添加公共变量**

变量支持文本和密码两种类型。

![](images/应用配置_添加公共变量.png)

**文本编辑变量**

![](images/应用配置_文本编辑变量.png)

**在实例中重定义变量值**

![](images/应用配置_实例重定义变量.png)

**审计**

审计用于查看变量修改记录。

![](images/应用配置_变量审计.png)

### 实例列表
实例列表数据来源于配置模型“应用实例”。

环境层支持添加实例，也支持为实例配置蓝绿标签。蓝绿标签用于控制蓝绿发布时实例的发布顺序。

#### 添加实例
添加实例有两种方式：新增实例数据，或关联已有实例。

实例列表支持查看、编辑和删除实例关联。

![](images/应用配置_实例列表.png)

**新增实例数据**

![](images/应用配置_环境层_新增实例.png)

新增实例的配置模型必须继承自“应用实例”模型，且模型层级为“应用实例”。

![](images/应用配置_环境层_新增实例条件.png)

**关联已有实例**

![](images/应用配置_环境层_关联已有实例.png)

实例下拉框会回显以下三类实例：

1. 应用环境和关联模块数据均为空的实例。
2. 应用环境为当前环境、关联模块数据为空的实例。
3. 应用环境数据为空、关联模块为当前模块的实例。

#### 蓝绿配置
蓝绿设置用于定义蓝绿发布中各标签的发布顺序，序号较小的标签优先发布。

![](images/应用配置_环境层_蓝绿设置.png)

实例也支持配置蓝绿标签。执行蓝绿发布时，系统会按标签顺序发布实例；未配置蓝绿标签的实例统一在最后一批并行发布。

![](images/应用配置_环境层_实例蓝绿配置.png)

### 清空配置
清空当前环境已重定义的配置后，环境会恢复使用模块层的默认配置。

### 复制配置
可以将当前环境的流水线配置复制到同一模块下其他未重定义的环境，也可以新增模块后复制当前环境配置。
